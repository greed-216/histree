# 从史料到网站数据

当前阶段的基础资料限于《资治通鉴》和二十四史，其他书籍待后续增补。录入时先用 [分段检索库](derived/history-library/README.md) 搜索，并按 [搜索与引用说明](../docs/HISTORY_LIBRARY.md) 导出可追溯片段；候选分段和索引建立不等于校核或录入完成。

沿用 `docs/DATA_PREPARATION.md` 与 `docs/templates/content-batch.json`。本轮仅采集、建立卷页索引与工作分期，不将自动提取结果写入生产数据库。

## 1. 保存来源

- 原文件只读保留；每个版本单独建来源，记录网址、取得日期、SHA-256、仓库提交或页面修订号。
- PDF排印页、原版叶码、卷次和电子文本行段号分别标注，不能互相冒充。
- 二十四史PDF底本未确认，引用写“GitHub仓库电子排印本，版本待考”；不能标成中华书局点校本或某古刻本。
- 用户TXT底本不详；用于检索定位，并对照另一来源核验关键字句。
- Kanripo文本保留 `#+` 元数据、方括号页码、异体字与原始行分隔；生成清洗副本时另存，不直接覆盖。

当前工作文本是二十四史目录根目录的25份 `*-EPUB全文.txt`；其他版本和原EPUB在 `backup/`。阅读和分段仅使用 [统一规范化库](derived/history-library/README.md)，转换出处和原元素定位见 [压缩转换审计](derived/epub-txt/README.md)，处理规则见 [规范化说明](../docs/HISTORY_TEXT_NORMALIZATION.md)。旧阅读/校改产物已清理，旧脚本归档供历史核查。

TeX和HTML候选来源的既有评估仅作历史参考：[TeX评估](../docs/TWENTY_FOUR_HISTORIES_TEX_REVIEW.md) · [HTML评估](../docs/CHINA_HISTORY_SOURCE_REVIEW.md)。当前不采用其替代选定工作版本；已发布引用快照继续保留原位。

## 2. 分卷、分纪年、分段

- 原始快照固定后才能生成稳定段落ID：书籍key + 版本key + 卷 + 段号。
- 保留原纪年，公元年另列；月份、干支日不在缺乏依据时强制换算。
- 追叙事件按实际发生时间标注，不能直接使用当前章年；不详用null。
- 同一段涉及多个独立行动可提取多个候选事件；每项回指同一段原文。

## 3. 一段原文同时分析三类对象

- 人物：姓名、异名、亲属、官职、生卒等分别建立有依据的陈述；别名先去重。
- 事件：时间、地点、行动、参与者、结果；保持可阅读的粒度。
- 关系：血缘、婚姻、收养、上下属等明确方向。合作、敌对、归附注明时期；共同参战不自动推出友好关系。
- 事件角色用person_events；人物之间的关系用person_relationships；事件先后不自动推导因果。
- 史家评论、传闻、引语与叙事事实区分；异文和冲突并列保存，不让模型自行裁决。

## 4. 生成草稿与证据

按现有批次规范产生people/events/person_events/person_relationships/sources/claims；所有内容状态为draft。
每个关键说法的claim写明subject_table、subject_key、field_path、claim_text、source_key、citation，以及“原文：…；核对说明：…”。
原文片段须能在指定版本中定位。校验通过只表示结构合规，不代表史实审阅通过。

## 5. 审阅后发布

先输出原文对照稿与JSON。核对同名异人、原始纪年、关系方向、版本分歧与重复事件，再使用现有校验/导入工具。全文资料不自动进入公开网站；页面展示经整理的条目与必要引用。
