# 猜人物

页面 `/ask?mode=guess` 使用签名匿名会话与 MySQL 事务限额，游戏 token 绑定调用身份。身份和原文只在猜中、揭晓或回合用尽后返回；姓名判定仍使用登记姓名、别名和字，不凭子串判赢。

## 预先准备题库与普通开局

独立迁移 `database/mysql/003-guess-bank.sql` 新增游戏元数据表，不修改人物、史料或发布状态。上线前显式执行迁移，再使用 `node scripts/prepare-guess-bank.mjs --apply` 准备已发布、有原文依据的人物；不带 `--apply` 只读统计。

初始简单档使用人工精选的熟悉人物名单，其他人物进入范围更广的困难档；这只是游戏设置，不是历史事实。每个人物使用稳定 ID 保存难度。服务启动时预热，约每四分钟更新目录，只为新增人物初始化分档，绝不覆盖已有玩家反馈调整。

新页面的“简单／困难＋年代”直接从已准备题库筛选抽取，不调用 AI。生卒年未知时使用已发布活动事件区间，未知年代只参与不限年代的抽选。每局开局仍重新核对人物和原文的当前发布状态。

身份、性别、自定义条件及旧数字难度请求保留模型筛选。高级筛选缓存按人物数据和难度版本的内容摘要复用，未变化的目录刷新不会使其失效。模型 worker 不开放工具，只能使用本局预选的公开史料；高级筛选遵守题库分档，不临时推翻玩家调档结果。

## 玩家难度反馈

完成至少一次有效对答并揭晓后，可选“太简单了／刚刚好／有点难”；不能为尚未揭晓、零回合或他人的游戏投票。客户端只提交本局 token 与评价，人物、难度版本和参与会话均由服务端确认。

每个签名匿名会话在同一人物、同一分档版本中只计一次，跨对局和重试也不会重复计票；不存邮箱、IP 或原始游戏 token。匿名会话去重不等于真人身份认证。

当前分档版本至少 12 条独立会话反馈、且至少 75% 指向另一档时自动调档；“刚刚好”计入总数。调档采用事务行锁，保存历史反馈、提升版本并清零本轮票数，避免旧反馈导致来回移动。调档前开始的游戏保留原难度；迟交的旧版本反馈归档但不参与新一轮计票。调档及去重记录重启后仍保留；游戏会话本身仍在内存中保留一小时。

## 验证

`pnpm --filter api test --runInBand` 覆盖游戏、准备、归属、取消、缓存与反馈；`pnpm test:mysql` 在独立 MySQL 8 库验证数据隔离和计票事务，并用 15,022 名合成人物通过实际 Nest HTTP 接口测量首次及连续开局耗时，强制模型调用为零。`node scripts/test-guess-browser.mjs` 验证手机和桌面反馈、失败重试及刷新恢复。

`node apps/api/dsh/guess-smoke.mjs`（另有 `--easy`、`--hard`、`--guess`）通过模拟模型验证真实 worker。`guess-era-eval.mjs --live` 是显式付费评测，不纳入部署。详见 [AI 入口](AI_GATEWAY.md)。

2026-10-19 的独立 Linux Node 24 / MySQL 8 测试（15,022 名合成人物）实测：题库准备 2,940 ms，首次 HTTP 开局 1,968 ms，预热后连续 30 次开局中位数 49 ms、P95 118 ms，模型调用 0。包含真实 HTTP、签名会话、限额和数据库读取；这是测试环境记录，不代表生产网络与真实史料规模下的耗时。
