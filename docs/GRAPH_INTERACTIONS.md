# 历史图谱阅读与交互

## 两个视图

- 人物关系（默认）：只显示人物与人物之间已记录的关系，以选中人物为中心加载直接关系，尚未整理关系的人物也可通过全库搜索打开。
- 人物与事件：只显示人物、事件和参与关系，连线文字说明参与角色，不混入亲属、政治或事件因果线。事件条目的局部图谱默认打开此视图。
- 两个视图均为自由网络，D3 在 Web Worker 中计算初始布局，之后停止模拟。聚焦、邻居突出和侧栏关系列表均以当前视图的关系为范围。切换视图保留探索中心并重新查询对应关系；重置筛选返回条目查找入口。
- 表格式时间布局不再作为图谱入口展示。

## 操作约定

- 单击节点：原地侧栏显示概述及相关关系；只有“阅读全文与出处”链接会进入条目页。
- 单击连线或其文字：选中关系，突出端点，侧栏提供方向、类型、说明和依据。20 个画布单位的透明线扩大命中范围；关系清单提供另一种选择方式。
- 拖动阈值为 6 个屏幕像素。超过阈值仅移动节点或画布，不改变选择、不导航。节点位置保留在当前视图，选择或打开侧栏不会重新布局。
- 两个视图都允许拖动节点。拖动空白处平移，按钮或 Ctrl/⌘+滚轮缩放，适应全图和恢复布局可恢复视野。
- 键盘 Enter/Space 选择，Esc 取消；关系视图方向键可移动节点。
- 人物聚焦支持一层、两层邻居，从数据库按需查询；双击或 Shift＋Enter 更换中心，路径支持返回上一级。前端 `/graph/:id` 自动选择人物或事件视图，`/graph` 为全库查找入口。
- 搜索在全库按姓名、别名、标签、简介匹配，输入防抖 250ms，最多显示 20 项；选择结果后加载该条目的子图。人物与事件视图的年份筛选在数据库展开之前生效，未知年份仍保留。隐藏的选中项保留详情并提示。
- 选择关系后按需加载对应 `/evidence/{subject_table}/{id}`；关系 ID 必须携带所属表，避免不同表同 ID 的证据错配。

## 验证

`pnpm test:graph` 覆盖拖动阈值、关系身份、邻居层数、年份稳定排序和边端点几何。浏览器实际操作验证单击不导航、拖动不改变关系选择、连线选择和史料加载。

当前不支持触屏双指缩放；触屏可单指平移并使用缩放按钮。拖动位置不持久化到数据库或跨视图保存。复杂大图仍需通过关系类型与聚焦缩小范围。

## 数据增长与读取预算（2026-09-30）

- `/search`：Supabase `search_entries` RPC，返回简要条目与 `has_more`，稳定排序后每页 20 项（最多 50）。不下载全表、不在浏览器扫描全库、不请求每次搜索的精确总数。精确姓名和别名优先。输入中的 `%`、`_`、反斜杠按字面匹配。
- `/graph-slice/:id`：`graph_slice` RPC，以中心进行一层／两层展开，最多 120 个条目、300 条关系。超出预算时 `truncated=true`，界面明确提示继续搜索或更换中心；返回每条边的原始表、ID、方向，保证两端都在节点集合内。上限代表当前子图的展示预算，不代表数据库总量。
- `/entry/:id`：`entry_detail` RPC，仅在选择条目后加载完整说明和事件阶段。子图只携带摘要，图谱搜索输入与画布独立，搜索不重新布局。
- 所有 RPC 使用 `SECURITY INVOKER`、RLS 与显式 `published` 条件。API 使用匿名 Supabase client；前端直连路径使用 `publicSupabase`，管理员的登录态不会放开公共查询的草稿范围。
- 搜索索引是已发布记录上的 `pg_trgm` GIN 表达式索引，自动随资料更新，无额外索引表或同步任务。保留中文子串匹配；不足三个字符的查询可能仍需扫描候选内容，应在更大规模时测量查询计划。
- 子图和选中详情使用最多 32 项、20 秒的内存缓存；重试绕过缓存。请求变化或组件离开时取消过期搜索／查询，Worker 在子图变化或卸载时终止。新发布记录可能在已缓存子图中最多延迟 20 秒出现。
- 关系清单仅展开后生成，初始显示 50 条，再按批展示。邻接节点、边组和连线文字复用计算结果，布局和相机变化不重复扫描全部关系生成文字。

### 发布顺序

1. 先按时间顺序应用 `20260930100000_graph_search_performance.sql`、`20260930110000_content_query_pagination.sql`、`20260930120000_ask_on_demand.sql` 三个迁移，创建搜索索引、分页和按需读取 RPC。不修改历史内容或发布状态；第二个迁移收紧 `claim_subject_visible` 对关系端点的已发布检查。普通 `CREATE INDEX` 会消耗资源并阻塞写入，安排维护窗口运行。
2. 再部署 API 与前端；仅使用静态站点直连 Supabase 的环境只需迁移与前端。迁移未应用时新页面会报告读取失败，不会降级成全表下载。
3. 使用匿名权限验证姓名／别名搜索、分页、人物／事件子图、两层展开、年份过滤、详情和草稿隔离。确认发布后的新条目能被搜索到。

### 本地验证

`pnpm test:explore` 使用本机 PGlite 运行真实迁移及 1,500 条虚构人物，覆盖超过 1,000 行的检索、75 页遍历无遗漏／重复、精确别名排序、特殊字符、子图预算、年份范围、完整详情、匿名及编辑者草稿隔离和两种读取路径的参数契约。API 控制器另有参数和 RPC 错误测试。

可对本地 Vite 运行浏览器测试（所有 Supabase 请求由虚构 PGlite 数据响应，不连接线上）：

```sh
VITE_SUPABASE_URL=http://127.0.0.1:54321 VITE_SUPABASE_ANON_KEY=histree-local-fixture VITE_API_URL= pnpm --filter web exec vite --host 127.0.0.1 --port 5179 --strictPort
HISTREE_EXPLORE_BROWSER=http://127.0.0.1:5179/histree/ node scripts/test-explore.mjs
```

若未安装 Playwright 浏览器，可设置 `HISTREE_CHROME_PATH` 指向本机 Chrome 可执行文件。浏览器测试覆盖搜索跳转、输入时布局保持、Worker 完成、两层展开、进入／返回子图、事件视图及搜索分页。数据库测试和浏览器测试不代表线上数据库的实际耗时；上线后需测量真实资料与目标设备上的响应和渲染。


## 其他读取的分页与按需加载

- 人物、事件、专题目录和后台分类使用 `content_page`，默认 20、最多 50 条，返回 `items`、`has_more`、本页关联对象 `labels`。排序包含稳定 UUID；不以精确总数作为翻页前提。旧 `/people`、`/event`、`/topics`、`/timeline` 和 `/evidence/:subject/:id` 读取接口同步改为分页对象，调用方须迁移旧数组契约。关系汇总每类一页，`has_more` 为各类合并结果。
- 人物/事件完整内容只在单条阅读时读取。条目关系使用 `entry_context` 每页 20 条，返回本页邻接条目；关系出处仅展开时读取。条目所属专题也可翻页。
- 专题正文一次读取单个专题；章节关联条目进入视口附近再按页读取，保留专题的勾选顺序。专题时间线在数据库先筛选专题、参与人物和年份，再翻页。地图展示当前事件页；未知年代位于末尾，年份筛选仍保留未知年代。已选事件单独读取完整说明。
- 陈述/引用按对象翻页，固定 `#claim-UUID` 链接按 ID 定位该条，不依赖它处在第几页。来源索引保留已有每页 50 条与精确计数方案（按来源索引查询）。取消请求覆盖新的 RPC 和单专题读取。
- 后台只读取当前分类；关系分类分为人物关系、事件参与、事件因果。人物、事件、关系、来源选择器搜索和翻页，已选 ID 独立回读。专题多选跨页保留完整 ID 顺序；保存时每批 100 个 ID 查询关联记录，避免每个条目两次请求。
- 问史不再生成全库快照：MCP 使用匿名 RPC 搜索每批 12 条、证据每批 10 条，单条详情按需读取。两层关系最多继续读取 5 个邻居，输出最多 40 条并明确截断。仅持久化本轮实际检索的引用，回答仍必须经引用校验后展示。保留现有状态/心跳 NDJSON 流与取消机制。
- `content_page(p_admin=true)` 仅允许管理员/服务端角色；公开读取显式检查发布状态及关系两端。SQL 参数通过白名单和 PostgreSQL 字面引用构造，API/直连共享参数校验。
- 当前分页采用稳定排序的 offset。翻页期间有新增/删除时可能改变页边界；页面不是一致性快照。中文短词和后台关系名称检索可能扫描候选记录；未把本地虚构测试当成生产性能数字。后续增长应根据实际查询计划决定游标分页、全文索引或进一步缓存。

`pnpm test:explore` 新增 1,205 条引用遍历、专题顺序、后台 ID 回读、公开关系端点隔离、问史按需 RPC 和并发引用账本测试。浏览器模式新增目录/证据分页、固定引用、章节懒加载；可同时设置 `HISTREE_ADMIN_BROWSER` 为配置了本地假 API 的第二个 Vite URL，验证后台跨页勾选、来源编辑和引用选择器。

`HISTREE_REMOTE_SMOKE=1 pnpm test:ask-runtime` 使用本地模型/RPC 假服务运行真实 DSH→MCP→引用验证，不连接模型供应商或线上数据库。DSH 需要 Node 24，与 Docker/CI 一致。
