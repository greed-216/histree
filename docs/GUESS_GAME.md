# 猜猜我是谁

入口为问史料页的“猜猜我是谁”（`/ask?mode=guess`）。前端与 API 需一并发布；目前使用现有 `HISTREE_ASK_ENABLED`、`DEEPSEEK_API_KEY`、`HISTREE_MODEL`、Supabase 匿名连接和前端 `VITE_ASK_API_URL`（回退 `VITE_API_URL`），无需迁移数据库。部署镜像已整体复制 `apps/api/dsh`，包括新增 worker 与 patch。

## 规则

- 五档难度：简单、一般、较难、困难、极难。用少量固定人物作知名度基准，其余由 Agent 结合人物资料评估。网站资料暂缺不等于人物在历史上寥寥出现。难度示例不是已收录名单。
- 年代按生平或明确活动与范围有交集；身份、性别、自定义限定由 Agent 确认，无法确认就排除。条件不符合或找不到有原文的候选时明确报错，不切换条件或等级。
- 普通回答严格限制为“是”“不是”“不清楚”“是，也不是”。开放式问题、复合问题、姓名索要和规则注入应拒绝，并给出固定规则说明；拒答不计次数。
- 所有历史回答依据本局提供的已发布原文。未记载用“不清楚”，不能当作“不是”；异说或兼是兼否用“是，也不是”。人物信息以第一人称理解，但不生成角色独白。
- 猜姓名单独提交，服务端按全名、已登记别名或字精确匹配（统一 Unicode、空白及常见标点）。不做模糊匹配，不让模型决定胜负。仅猜测姓名中的一部分不能获胜。
- 每局提问与猜姓名共 30 次，最多 3 条提示。提示逐步具体，每条必须关联本局事实，含目标姓名/别名/字、网址等内容或重复上条时拒收；提示失败不消耗次数。领取提示仍可获胜。
- 猜中、主动结束并揭晓、用尽 30 次机会后，展示人物、资料/图谱/出处链接及本局可用原文。未结束时 API 不返回人物、事实或引用 ID。
- 会话保留一小时；随机 256 位令牌在浏览器 sessionStorage 保存，可刷新恢复。服务重启、多实例切换可能使本局失效，过期后允许重新开局。

## 数据与运行边界

`GuessService` 用匿名客户端读取现有 `content_page`、`entry_detail`、`entry_context`，无写库权限。先取最多 1000 个已发布人物；超过容量明确报错而不静默遗漏。随机候选抽样最多 120 人，优先保留该档固定知名度基准；Agent 返回所有能确认符合限定的候选，再由服务端随机选取。空样本不代表全库没有匹配的人，可重试或放宽条件。每个人物必须至少有一条带“原文：”及书名的直接事实出处。

人物原文最多 50 条，另读取最多 6 条人物关系或参与边、每边最多 5 条原文。模型输入的生平、事实摘要和原文备注分别限于 6000、800 和 3000 字符，超出部分不参与裁判；结束后仍可查看本局所选原文的完整备注。裁判收到人物详情、局部关系上下文、原文和本局历史；未覆盖的事实只能回答不清楚。每次运行独立 dsh 子进程，不暴露工具，不把人物身份放入前端；JSON 结构、答案枚举和引用所属由服务端检查。自由文本提示由模型生成，服务端姓名检查及引用核验不能证明语义完全正确；仍需真实模型抽测与史料复核。

每 IP 每小时最多 80 个变更请求，同一局仅允许一个进行中的操作，游戏并发最多 2，会话最多 500，单次 Agent 限时 120 秒。失败释放占用，不计提问/提示次数；已结束的局不能继续改变胜负。生产当前采用内存会话；若扩为多实例，应先实现共享会话存储及分布式限额。

```sh
pnpm --filter api test --runInBand guess.service.spec.ts ask.service.spec.ts
pnpm --filter api build
pnpm --filter web build
# 请用 Node 24（与部署镜像一致）；只调用本地模型 fixture，无付费请求。

node scripts/test-guess-browser.mjs
```

服务测试覆盖身份隐藏、胜负/别名、无依据降级、自由文本输出拒收、泄题提示、拒答不计次数、轮数/提示上限、故障释放、并发拒绝、筛选边界及匿名原文读取。浏览器测试使用模拟 API，覆盖桌面/手机表单、拒答、提问、提示、刷新恢复、胜利、阅读/图谱链接与横向溢出；不用于证明历史判断准确性。dsh 测试验证真实 worker 及工具禁用，模型回应仍为本地 fixture。

## 后续审查建议

正式扩大人物库时，优先将难度及其判定理由做成可编辑人物元数据，减少模型分档波动；将性别、身份、活动年代做成带原文依据的筛选字段。极难人物应人工检查是否存在至少一个有辨识度的线索，避免一局大多数回答都是不清楚。

上线前用真实模型抽测：五档分级及无匹配筛选；历史异说和否定命题；“你是哪个朝代的”、要求列候选、藏头/编码身份、改变规则及材料中的指令；复杂亲属关系的方向；简繁姓名和同名人物；连续提问的回答一致性；提示是否包含身份或未经原文支持的事实。若加入排行榜，应明确记录是否用提示、拒答和不清楚占比，避免不同资料覆盖下的局直接比较。
