# Histree 连环画故事

把经典故事做成适合翻阅的小人书：故事讲完整，图片按需下载，对人物和原文感兴趣的人能继续点进去阅读。

## 确认工作范围

- 先读项目 `AGENTS.md`，核对当前工作区与最新 main；主工作区有无关改动或版本落后时，在独立工作区工作，只纳入本次路径。不要从旧检出覆盖已上线的阅读器。
- 先看当前检出中的 `docs/STORIES.md`、故事目录 `apps/web/src/data/stories.json` 和同类 `docs/stories/<slug>.json`。本 Skill 随项目维护，不依赖 Codex 全局安装；主工作区缺少应用文档或脚本时，先核对最新 main，使用有完整文件的当前工作区。
- 按用户要求停在选题、脚本、试画、录入或上线阶段；已有上传、录入、发布授权时在该范围内继续。只要方案或脚本时，不自动生图或上线；本次授权不等于以后的所有故事都可以直接发布。
- 故事目录属于娱乐内容，不写入人物／事件事实库，不推进历史书籍的连续录入账本。另行要求事实库录入时才转到项目 `histree-history-ingest` 流程。

## 脚本与分镜

1. 选适合短篇图画叙事的故事，分清说理寓言、史传记载和艺术改编。核对古书原文及具体篇章／段落，保存定位、摘引和版本信息，不把现代改写或搜索摘要当原文。
2. 默认沿用已确认的古早连环画／早期国产动画感觉：流畅墨线、戏曲式人物、平涂设色、纸本质感。以现有《徙木立信》原画和本次用户审美要求为准，不能只凭“复古”一词换成现代动漫风。
3. 格数随故事长度、转折和人物关系安排，**不固定八格**。一格表达一个主要动作；简短故事可六格，复杂故事可以十格或更多，不为凑格数重复画面。
4. 每格写清标题、画面、图下注文、替代文本，以及人物、衣色、关键器物和时空连续性。先把首尾和因果讲清楚，再提炼寓意；不加考题。交付结构包含开场、连环画、后记解释、寓意与出处。
5. 白话对白、神态、布景和现代寓意与史料原话分开，写进审核记录的改编说明。未知人物、地点、年代不补造；寓言中的匿名角色不强配真人。

## 出图与审图

- 生图或画面修改使用当前可用的 imagegen Skill 和工具，按工具要求保存原画与最终提示词到项目目录。不把占位图当成正式连环画，也不因多篇任务改用未经用户选择的 API 生图路径。
- 多篇故事分别准备提示词和素材；明确格数、行列、阅读顺序及同一人物造型。图片尽量只画插图，图下文字由网页排版；已有批准原图内的文字不擅自重画，裁切位置按实际画面确定。
- 逐格检查数量、顺序、关键动作、器物和身份连续性。尤其核对会改变含义的画面：赛马哪一方领先、谁拿到赏物、受伤及请罪是否画成了原文没有的暴力。不要把“生成成功”当审图通过。
- 批准的原画不覆盖，修改生成新版本。新故事的编辑检查如实记录；沿用用户已确认的画风，不等于用户逐幅确认了所有新画。

## 网页图片、录入与上线

进入图片准备或发布阶段时，读 [图片与录入流程](references/images-and-release.md)。其中包括可复用的压缩命令、目录字段、OSS 边界与验收方法。

- **普通阅读用 WebP 单格图，书架用小封面，原画只在主动打开整页时下载。** 保留原画、原始哈希与裁切记录；不要只把大 PNG 改后缀，或仍下载整张原画后在浏览器里裁切。
- 复用仓库 `scripts/prepare-story-images.py`，不复制另一套压缩脚本。当前基线为单格保留裁切像素、quality 86，封面最长边 360px、quality 80；按源图清晰度与文件体积判断效果，放大检查线条、颜色和纸纹。
- 复用已有阅读器的预加载：开场准备前六格，阅读时提前后五格，后台最多两个并发、低优先级。新增故事只需完整填写单格元数据，无需为每篇重新实现预加载。
- 为真实人物绑定已核对的稳定 ID；结尾和目录保留可点击原文链接，站内原文定位到段落。保留原有整屏翻页、全屏入口、随机故事及人物／出处新标签页打开的行为。
- 图片上传、目录写入、构建通过、CI 通过、实际上线分别记录。只有公开图片哈希核对、实际运行版本和浏览器阅读验收均完成，才报告上线。
